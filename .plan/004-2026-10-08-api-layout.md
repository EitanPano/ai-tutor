## Goal

1. **Backend layout for scale.** Each HTTP module is `backend/src/api/<m>/` with `route.ts` (a declarative table),
   `controller.ts` (plain handlers), `service.ts` (domain rules), `validation.ts` (Zod request schemas) and `index.ts`.
   HTTP-less domain services live in `backend/src/services/<s>/`, Express middleware in `backend/src/middleware/`,
   infrastructure stays in `backend/src/lib/`.
2. **DRY and readable.** One copy of each cross-cutting concern (validation, rate limiting, the AI kill switch, session
   cookies, error messages, SSE plumbing); chains of three or more branches on one discriminator become lookup tables.
3. **Conventions written down and applied.** Boolean names start with `is`/`has`/`can`/`should`/`was`/`did`, in the
   backend, the API contract and the frontend; `.claude/rules/` records the boolean and lookup-map rules and the new
   layout.
4. **`bunx fallow` findings cleaned up.** Dead exports and the reported clone groups are gone.

  (28 files), typecheck and lint clean in both workspaces. Every task leaves `bun run typecheck`, `bun run lint` and

- A2. Behaviour does not change, except where a task says so (the wire-field rename in Task 14 and one unified refusal
  message in Task 2). A test changes only for a moved path, a renamed symbol or a reshaped helper that the task names.
- A3. Integration test files share one Vitest worker and keep several apps with different `config` alive at once. So
  route and controller modules are singletons that read every dependency per request through `ctxOf(req)`; nothing
  captures a service, config value or limiter at import time.
- A4. Express 5.2.1 / router 2.2.0 facts (verified in `backend/node_modules`): `req.query` is a getter without a setter
  (write it with `Object.defineProperty`); `req.params` is shared by the handlers of one `router.verb(...)` call; async
  rejections reach the error handler; `req.app` is the root app inside a `Router()`; a 4-parameter function is treated
  as an error handler, so handlers and middleware declare at most `(req, res, next)`.

## Risks

- Path churn hides behaviour changes → the move (Task 3) is its own commit with no behaviour change.
- SSE extraction could leak the generation lock → Task 8 keeps the two-phase try/finally and the existing suites cover
  sync throws, disconnects and persistence failures.
- `app.locals` typing → no `Express.Locals` augmentation; `ctxOf` casts once and fails loudly when the context is
  missing.
- Shared route singletons across apps in one test worker → everything resolves through `ctxOf(req)` per request (A3).
- The wire rename breaks old clients → acceptable: no hosted environment, both sides live here; contract, types and
  tests move in one commit.
